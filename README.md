# templates

Nix flake templates built on [flake-parts](https://flake.parts) and
[flake-file](https://github.com/denful/flake-file). Each template ships a
dev shell, formatting, and pre-commit hooks, so a new project starts with
the same tooling.

## Quick start

Run inside an empty directory:

```sh
nix flake init -t github:soriPhoono/templates
```

Then enter the dev environment:

```sh
nix develop   # or: direnv allow
```

The dev shell installs the pre-commit hooks and provides `nil`, `statix`,
`deadnix`, `nixfmt-rfc-style`, `markdownlint-cli` and `treefmt`.

## Templates

| Template            | Status                | Description                                                  |
| ------------------- | --------------------- | ------------------------------------------------------------ |
| `empty` (`default`) | Available             | Bare flake and dev shell                                     |
| `rust-project`      | Available             | Cargo workspace, crane, rust-overlay, clippy and test checks |
| `python-uv-project` | In repo, not exported | `src/` layout, uv, ruff, pyright, pytest                     |
| `rust-tauri-app`    | Available             | Tauri 2 shell with a Nuxt UI frontend, pnpm                  |

> [!NOTE]
> Only `empty` and `rust-project` are registered in
> `templates/default.nix`. The other two cannot be used with
> `nix flake init -t` until they are registered.

Select a template by name:

```sh
nix flake init -t github:soriPhoono/templates#<name>
```

## Repository layout

```text
flake.nix            generated by flake-file, do not edit
modules/             flake-parts entrypoint and input declarations
flake-system/        shared parts: shells, treefmt, pre-commit, systems
templates/           one standalone project per template
templates/default.nix  template registry (flake.templates)
```

Every template is a full standalone project with its own `flake.nix`,
`flake.lock`, `modules/` and `flake-system/`. Keep `flake-system/`
identical between the root and each template unless a template needs a
deliberate difference:

```sh
diff -r flake-system templates/<name>/flake-system
```

## Development

Regenerate `flake.nix` after editing `modules/inputs.nix`:

```sh
nix run .#write-flake
```

Validate and format:

```sh
nix flake check     # add --no-build for a fast evaluation-only pass
nix fmt
```

### Adding a template

1. Copy `templates/empty/` to `templates/<name>/`.
2. Add inputs in the template's `modules/inputs.nix` and modules in its
   `modules/default.nix`, then run `nix run .#write-flake` inside it.
3. Register it in `templates/default.nix` with `path` and `description`.
4. Run `nix flake check` at the root, then instantiate the template in a
   temporary directory and check it standalone:

   ```sh
   nix flake init -t .#<name>
   nix flake check
   ```

> [!TIP]
> `rename-project <dir> <name>` in the dev shell replaces `templates` with
> a new project name across a directory.

## CI

- `flake-check.yml` runs `nix flake check` on pushes to `main` and on pull
  requests.
- `update-flake-lock.yml` opens a weekly PR updating the root `flake.lock`.
  Template lockfiles are not updated by it.
